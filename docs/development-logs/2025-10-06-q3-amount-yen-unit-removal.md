# 第3問（財務諸表問題）金額選択の"円"単位削除

## 日時

2025-10-06

## 問題の背景

### ユーザーフィードバック

ユーザーから、第3問（Q3_FS問題）の金額選択後に「円」という単位が表示されており、他の金額表示（通常の金額フィールド）と統一感がないとの指摘を受けました。

### 症状

**修正前の表示**:

- 金額選択ドロップダウン: 「金額を選択 ▼」
- 選択後の表示: 「500,000円」
- モーダル内の選択肢: 「400,000円」「450,000円」「500,000円」「550,000円」

**問題点**:

- 通常の金額フィールドは「500,000」と単位なしで表示
- BlankSelectorで選択した金額のみ「500,000円」と単位付きで表示
- 視覚的な統一感が損なわれる

## 原因分析

### 技術的原因

**ファイル**: `src/components/cbt/BlankSelector.tsx`

**問題のコード** (Line 66-68, 148-151):

```typescript
// Line 66-68: ボタンに表示される選択済みテキスト
if (typeof choice === "number") {
  return choice.toLocaleString("ja-JP") + "円";
}

// Line 148-151: モーダル内の選択肢表示
const choiceText =
  typeof choice === "number" ? choice.toLocaleString("ja-JP") + "円" : choice;
```

### 根本原因

1. **数値の表示形式**: 数値型の選択肢に対して `toLocaleString("ja-JP")` で桁区切りフォーマット後、"円"を追加
2. **視覚的不統一**: 通常の金額フィールド（`amountText`スタイル）は単位なしで表示されるため、BlankSelectorで選択した金額のみが異なる形式になる
3. **設計意図**: 財務諸表では金額は数字のみで表示するのが標準的

## 修正内容

### 修正理由

1. **視覚的統一性**: 財務諸表内の全ての金額表示を統一（単位なし）
2. **標準的な会計表示**: 財務諸表では金額は数字のみで表示するのが一般的
3. **ユーザビリティ**: 一貫した表示により、ユーザーの認知負荷を軽減
4. **シンプル化**: 不要な情報（"円"単位）を削除し、視認性を向上

## 技術メモ

### toLocaleString() の仕様

```typescript
// 日本語ロケール
(500000)
  .toLocaleString("ja-JP")
  (
    // "500,000"

    // 通貨形式（今回は使用しない）
    500000,
  )
  .toLocaleString("ja-JP", { style: "currency", currency: "JPY" })(
    // "¥500,000"

    // 単純な桁区切り（今回採用）
    500000,
  )
  .toLocaleString("ja-JP"); // "500,000"
```

**選択理由**:

- 財務諸表では通貨記号（¥）も単位（円）も表示しない
- 桁区切りカンマのみを適用する標準的な表示形式を採用
