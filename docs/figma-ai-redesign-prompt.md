# Figma AIリデザイン依頼用プロンプト案

## 目的
- 現状の画面構成と機能要件を維持しつつ、Figma AI（Design Generator）に対してモバイルUIのリデザインを依頼するための情報整理
- プロンプトをそのままコピーすれば、主要画面のデザインやコンポーネント改善を指示できる状態にする

## アプリ概要と利用シーン
- アプリ名: 簿記3級問題集「確実復習」
- 目的: 日商簿記3級の受験生が、仕訳・帳簿・決算書の問題を解き、間違えた問題を復習しながら合格力を高める
- 利用シーン: 通勤・通学時間などの隙間時間にスマホで学習/復習し、進捗と弱点を可視化する
- ユーザー像: 20〜40代の社会人・学生。簿記学習は初級〜中級レベルで、シンプルかつ信頼感のあるUIを好む
- ブランド/トーン: 信頼感のあるブルー（#2196F3）を基調に、達成感を支えるグリーン（#4CAF50）をアクセントにした落ち着いた学習アプリ。可愛いよりも実務的だが親しみやすいテイスト

## 画面構成と主要機能
### グローバルナビゲーション
- ボトムタブ4本: ホーム / 学習 / 復習・進捗 / 設定
- 現状は絵文字アイコン。Figmaでは統一感のあるベクターアイコンセット（例: outlined style）に刷新したい
- iPhone 13相当（375×812）を主レイアウトとし、タブレット時は余白が広がる前提。レスポンシブに対応しやすい余白設計（8ptグリッド）を意識

### 主要画面の要件
- **ホーム（Home）**
  - ヒーロー: アプリタイトルとサブコピー「間違えた問題を確実に潰す学習アプリ」
  - 3つの主要CTAカード
    - 学習開始: 学習タブへ遷移
    - 復習: 復習タブへ遷移
    - 統計・進捗: 復習タブの統計タブへ遷移（現状同じ遷移だが将来的に専用画面想定）
  - カード内にアイコン/見出し/説明文/行動ラベル。Emojiではなく統一アイコン＋視覚的階層を持たせたい

- **学習タブ トップ（Learning Dashboard）**
  - ヘッダー: 「学習」タイトル、キャッチコピー、全問題数（例: 全370問）
  - ボタン: 「全問題順次進行」（仕訳→帳簿→決算書を通しで解く）カード。内訳とCTAボタンを配置
  - カテゴリカード: 第1問（仕訳）、第2問（補助簿・伝票）、第3問（決算書）。各カードに以下を表示
    - アイコン、カテゴリ名、副題
    - 説明文、配点、試験での出題数・目安時間
    - 練習問題数/進捗バー（完了数/総数）
  - ローディング時はSkeletonを表示。最終デザインでは骨組みよりも柔らかなローディング表現を検討

- **学習タブ カテゴリ詳細（Category Detail）**
  - ヘッダー: カテゴリアイコン、名称、副題、説明、試験情報、総問題数
  - フィルタブロック
    - 難易度（基礎/標準/応用の3区分、複数選択可。件数を表示）
    - 問題類型（カテゴリごとに異なるタグ。複数選択可、件数表示）
    - 学習状況（すべて/未学習/間違い経験/弱点克服/復習推奨など単一選択）
    - 最近解いた問題を除外（トグル）。除外対象件数を表示
  - 問題リスト
    - 各カードにタグバッジ、難易度バッジ、問題文プレビュー（2行程度）、学習ステータス（未学習/間違い回数/最近解答）
    - タップで問題画面へ遷移（フィルタ条件を維持したまま）
  - 情報量が多いため、視線誘導と折りたたみを検討

- **学習タブ 問題表示（Learning Question）**
  - 上部に問題ナビゲーションバー（前/次への遷移、進度表示、カテゴリ名）。タブUIではなく上部固定バーで表現
  - コンテンツ
    - 質問ヘッダー: 問題ID、カテゴリ、難易度、戻るボタン
    - 問題本文
    - 解答フォーム: 質問タイプに応じてフォームが変化（仕訳入力、補助簿入力、選択式、数値入力、複数空欄選択など）
  - 解答送信後はモーダル「AnswerResultDialog」を表示
    - 正誤、解答時間、解説（テキスト/表形式）、正答例
    - 「次の問題へ」「復習に追加」などのボタン

- **復習タブ ダッシュボード（Review Dashboard）**
  - ヘッダー: タイトル/サブタイトル
  - タブ切り替え: 「復習」「統計」
  - 復習タブ内容
    - サマリ統計（総復習アイテム数、重点復習数、克服済み数）。円形メーターやバッジで表現
    - 主要CTA: 「重点復習を開始」「全て復習」カード
    - 分野別弱点カード: アイコン、復習対象数、推奨コメント、優先度バッジ、進捗バー
    - 復習対象ゼロのときの祝福系エンプティステート（イラスト/アイコンと「学習を始める」ボタン）

- **復習タブ 統計（Review Statistics）**
  - 全体統計カード: 解答済み総数、正答率、累計学習時間
  - 分野別進捗グリッド: カテゴリアイコン、名称、正答率、進捗バー
  - データ更新カード: 最新化ボタンとデータ説明文

- **復習タブ 問題表示（Review Question）**
  - 学習タブと同じ問題UIだが、復習セッション前提
  - 「復習対象に残す/外す」など復習特有のテキストを含める（現状は学習と同じViewを使用）

- **設定タブ（Settings）**
  - セクション一覧（カード型）
    - 復習システム説明（条件やルールの文章 + アイコン付きインフォ項目）
    - テーマ設定（ライト/ダーク/システムの選択モーダル）
    - アプリ情報（アプリ名/バージョン/データ保存方法）
    - データベース管理（リセットボタン、警告テキスト）
    - （開発モードのみ）テストデータ作成モーダルの起動ボタン
    - 学習のコツ（番号付きリスト）
  - テーマ選択モーダル: リスト形式でテーマを切り替え。ラジオボタン風の選択状態を視覚化
  - デベロッパーモーダル: テストデータ生成の説明と実行ボタン（開発用だがデザインは整えておきたい）

- **共通コンポーネント**
  - AnswerResultDialog: 正誤結果、解説、正答例、学習ログ情報を表示するモーダル。ライト/ダーク両対応
  - Skeleton/Loading: カードやリストのローディング状態をシェイプベースのプレースホルダーで表現
  - Progress UI: 線形/円形プログレス、ステータスチップ、タブ切り替え

## デザイン改善で伝えたいポイント
- 絵文字中心のアイコンを、統一感のあるベクターアイコン（例: 2pxアウトライン）へ置き換え
- 情報密度の高い画面（カテゴリ詳細、復習ダッシュボード、統計）で視線誘導を最適化
  - フィルタブロックは領域を整理し、チップやトグルで状態が一目で分かるように
  - カードの余白・影の階層を統一し、CTAボタンはタップ領域を明確に
- ブランドカラー（ブルー/グリーン）を軸に、ニュートラルカラーで可読性を確保
- アクセシビリティ: WCAG AA相当のコントラスト、テキストサイズ14pt以上を目安に、色だけでなくアイコンやラベルで状態を伝える
- ダークモードの配色変換指針も合わせて考慮（背景を#121212前後、ブルー/グリーンは彩度を抑える）
- 成果物として、主要画面8枚 + AnswerResultDialogモーダル + アイコン/チップ/ボタンなどのコンポーネント定義を依頼
